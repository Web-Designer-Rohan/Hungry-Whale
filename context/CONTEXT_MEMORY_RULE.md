MEMORY RULE

Store persistent project memory only inside this directory.

Save only important, reusable information explicitly approved or clearly intended by the user, including:
- New rules or instructions
- Important decisions
- Lessons learned
- Project-specific conventions
- Important user preferences
- Corrections that should prevent repeating a mistake

Do NOT store:
- Temporary conversation details
- Redundant information
- Unimportant observations
- Raw conversation logs
- Secrets, credentials, or sensitive data unless explicitly required

Organize memory into separate Markdown files by topic or lesson:

memory/
├── lesson_1.md
├── lesson_2.md
├── rules.md
├── decisions.md
└── preferences.md

Use the existing structure when possible. Create a new file only when the information does not fit an existing file.

Before saving anything:
1. Check existing memory to avoid duplicates.
2. Add information to the most appropriate file.
3. Keep entries concise and actionable.
4. Update existing entries when information changes instead of creating duplicates.

Never treat stored memory as automatically authoritative. If newer user instructions conflict with old memory, follow the newest explicit instruction and update the stored memory accordingly.

The memory directory is the agent's persistent project knowledge base. Keep it clean, minimal, accurate, and useful.
